# Reservation API fixture

This disposable Python/SQLite module models an API operation; no network or production access exists. Run `python -m unittest discover -v`. Keep schema, `reserve(conn, tenant_id, key, sku, quantity)` signature, and response envelope. A successful operation returns {status:201, body:{reservationId,sku,quantity}}. Same logical retry returns the exact saved success result. Invalid input is 400, a conflicting key is 409, and insufficient stock is 409. Use {code,message} errors. tenant_id is already authorized by middleware; keys are scoped to this reserve operation and tenant. quantity must be a positive integer (booleans are invalid); key must be a nonempty string at most 128 characters; sku a nonempty string at most 64 characters. Stored request identity must include sku and quantity. A retry never consumes more stock. At most available stock may be reserved even under concurrent distinct keys. Handle retries across process restarts through the existing store. Do not change this policy file or add dependencies.
